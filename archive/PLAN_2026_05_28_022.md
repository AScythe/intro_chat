# PLAN_2026_05_28_022 — Modularize & Clean + Improve Architecture

## Problem Statement

The codebase has accumulated structural and code-level issues: mixed concerns in `routes.py` (QR generation inline), view-state bloat in large frontend pages (RoomPage 318 lines, ChatPage 281 lines), and DRY violations (FALLBACK_PROMPTS duplicates CONVERSATION_PROMPTS). These don't affect correctness but increase cognitive load and maintenance risk.

## Goals & Non-Goals

### Goals
- Run both Phase 1 evaluations (read-only scan) in parallel
- Present findings with P0/P1/P2 (architecture) and scope-categorized (modularization) priorities
- Apply approved changes in parallel batches with [ARCH] and [CLEANUP] flags
- All tests pass after every batch

### Non-Goals
- No behavior changes, bug fixes, or new features
- No changes to test logic or test names
- No frontend visual changes

## Phase 1a — Architecture Evaluation (improve-architecture)

### Findings

| # | Area | Priority | Finding |
|---|------|----------|---------|
| 1 | Import hygiene | **P1** | `hooks/useChatRequest.ts:5` imports `'./useDemoMode'` instead of `'@/hooks/useDemoMode'` — the `@/` alias is configured and used everywhere else |
| 2 | Module boundaries | **P1** | `routes.py:167-182` — QR code generation is inline inside a route handler. QR encoding, base64 conversion, and data URI construction should be a shared utility |
| 3 | Config placement | **P2** | `routes.py:17` — `DEFAULT_ROOMS` is a data constant defined inside `routes.py` instead of `config.py` |
| 4 | Module boundaries | **P2** | `routes.py:24` — SPA index.html path (`FRONTEND_DIST_DIR`) is re-constructed inline in `index()` handler; already computed in `__init__.py` |

### Approved candidates (for user to approve)

**Candidate ARCH-1** (P1) — Fix import alias in `useChatRequest.ts`
- File: `hooks/useChatRequest.ts:5`
- Change: `'./useDemoMode'` → `'@/hooks/useDemoMode'`

**Candidate ARCH-2** (P1) — Extract QR generation utility
- File: `routes.py:167-182`
- Change: Move QR generation to `app/qr_utils.py` as `generate_qr_data(url) -> str`, update routes.py to call it

**Candidate ARCH-3** (P2) — Move DEFAULT_ROOMS to config
- File: `routes.py:17` → `config.py`
- Change: Move `DEFAULT_ROOMS` to `config.py`, import from there in `routes.py`

**Candidate ARCH-4** (P2) — Use shared FRONTEND_DIST_DIR path
- File: `routes.py:index()`
- Change: Export `FRONTEND_DIST_DIR` from `__init__.py`, import in `routes.py`

## Phase 1b — Modularization & Cleanup Evaluation (modularize-and-clean)

### Findings

| # | Scope | Priority | Finding |
|---|-------|----------|---------|
| 1 | Mixed concerns | **P1** | `state.py:24-35` — `CONVERSATION_PROMPTS` is static data, not state. Should live in its own module |
| 2 | DRY | **P1** | `frontend/src/config/constants.ts:16-22` — `FALLBACK_PROMPTS` duplicates the first 5 prompts from `state.py`'s `CONVERSATION_PROMPTS`. These should share a single source of truth (via API) |
| 3 | Large file | **P1** | `frontend/src/pages/RoomPage.tsx` (318 lines) — 5 view states (`selecting`, `roomSelected`, `waitingResponse`, `accepted`, `matchFound`) in one component |
| 4 | Large file | **P1** | `frontend/src/pages/ChatPage.tsx` (281 lines) — 6 chat states (`loading`, `chatting`, `timeUp`, `extended`, `connecting`, `result`) in one component |
| 5 | Type safety | **P2** | `state.py` — `active_users`, `active_matches`, `waiting_queue` are untyped dicts (`{}`). Could benefit from TypedDict |

### Approved candidates (for user to approve)

**Candidate CLEANUP-1** (P1) — Extract CONVERSATION_PROMPTS to `app/prompts.py`
- File: `state.py:24-35` → new `app/prompts.py`
- Change: Move prompts list to `prompts.py`, import in `state.py` (re-export for backward compat)
- Test: Existing tests reference `CONVERSATION_PROMPTS` via state — verify the re-export works

**Candidate CLEANUP-2** (P1) — Deduplicate FALLBACK_PROMPTS
- File: `frontend/src/config/constants.ts:16-22`
- Change: Remove `FALLBACK_PROMPTS`, fetch prompts from API instead. Update `ChatPage.tsx` to use API response
- Note: ChatPage currently imports `FALLBACK_PROMPTS` from constants; change to fetch from `/api/prompts`

**Candidate CLEANUP-3** (P1) — Split RoomPage view states into sub-components
- File: `RoomPage.tsx` → extract new components per view state
- Change: Extract each view state block as a separate component

**Candidate CLEANUP-4** (P1) — Split ChatPage view states into sub-components
