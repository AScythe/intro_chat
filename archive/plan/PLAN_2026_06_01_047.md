# PLAN_2026_06_01_001

## Problem Statement

The primary CTA button (sage green, `variant="default"`) uses `--primary: hsl(105, 12%, 67%)` which is highly desaturated. When the button is **enabled** (full color), it looks too close to its **disabled** state (`opacity-50`). Users can't easily distinguish when the primary action button is actionable vs. unavailable. The primary button also has an unnecessary hover color shift (`hover:bg-primary/90`) which conflicts with its role — primary CTAs should have a fixed, prominent color that draws the eye without needing hover interaction.

## Goals & Non-Goals

### Goals
- Increase `--primary` saturation so the enabled state is clearly distinct from disabled
- Remove hover color change from primary (default) button variant (keep only the lift effect)
- Update DESIGN_SPEC.md with new color values
- Preserve the "Warm Sanctuary" ambiance — the change should be subtle, not bright

### Non-Goals
- No changes to secondary/outline button behavior
- No changes to button variant structure or component API
- No changes to page logic or layout
- No behavioral changes

## Success Metrics

1. Primary button enabled state is visually distinct from disabled state
2. Primary button has no color shift on hover (only `-translate-y-0.5` lift remains)
3. `npm run build` passes
4. `npx tsc --noEmit` passes
5. DESIGN_SPEC.md updated with new color values

## Technical Approach

- **CSS variable change:** Modify `--primary` HSL values in `global.css` to increase saturation (~50% increase from base) and slightly reduce lightness for depth
- **Button variant change:** Remove `hover:bg-primary/90` from the `default` variant in `button.tsx`, keep `hover:-translate-y-0.5`
- These are pure CSS + class-name changes — no JavaScript logic affected

### Architecture & Design Decisions

- `--primary` is the single source of truth for the primary color (buttons, icons, rings, accents). Changing it in `global.css` propagates consistently to all consumer elements via `tailwind.config.js` (`hsl(var(--primary))`).
- The `default` button variant's hover behavior is: was `hover:bg-primary/90 hover:-translate-y-0.5`, becomes `hover:-translate-y-0.5`. No color change on hover — primary CTAs are fixed-color by design.
- HSL values chosen: Light `105 18% 64%` (was `105 12% 67%`), Dark `105 16% 52%` (was `105 10% 56%`). These increase saturation by ~50% from a very low base — enough to be noticeable without breaking the muted warm theme.

## Open Questions & Risks

- **Risk:** `--primary` change also affects non-button elements (icon circles, checkmarks, focus ring). This is acceptable — it keeps the color system consistent. Perceived impact: accent elements will have slightly more green presence.
- **Risk:** Dark mode contrast could be affected. The dark mode primary changes from `hsl(105, 10%, 56%)` to `hsl(105, 16%, 52%)` — slightly more saturated and darker, maintaining contrast on dark backgrounds.

## Grill Outcomes

### Dimension: Button tier system
- Decision: Two-tier system — Primary (fixed color, no hover shift) and Secondary (outline, hover-activated)
- Rationale: Primary CTAs should draw the eye immediately; secondary actions are supplementary
- Impact: Primary buttons get their hover color change removed; this is the correct behavior

### Dimension: Color values
- Decision: Light `105 18% 64%`, Dark `105 16% 52%` — Option A from brainstorm
- Rationale: 50% saturation increase from a very low base — subtle but clearly distinguishable
- Impact: All `--primary` consumers get slightly richer green

### Dimension: Hover behavior of primary
- Decision: Remove `hover:bg-primary/90`, keep `hover:-translate-y-0.5`
- Rationale: Primary buttons need fixed color; the lift provides tactile feedback without color confusion
- Impact: One class-name change in button.tsx
