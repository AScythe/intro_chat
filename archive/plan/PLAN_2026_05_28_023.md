## Problem Statement

The old tool selection priority chain ("graphify first → cocoindex next → ast-grep next → Grep next") in AGENTS.md and 6 skill files has three problems:

1. **Duplicate numbering** (two `3.` entries at lines 112-113) and a linear "priority chain" framing that contradicts the actual design — layers are not mutually exclusive, multiple tools should be combined when a task crosses types.
2. **Inconsistent naming** across files: "Context Window Discipline", "Smart Tools", "Smart Tools: Graphify + AST-Grep + Semantic Search", "Smart scanning", "Smart Verification", "Smart Scanning Tools" — 6 different headers for the same concept.
3. **Stale prerequisite checklists** in all 6 skill files still say "Consult tools in order of priority: graphify → cocoindex → ast-grep → grep".

Additionally, `DOCUMENT_GUIDELINES.md` references "Context Window Discipline" by name (lines 230, 394, 397) with an outdated description "Grep→Read patterns".

## Grill Outcomes

### Dimension: Assumptions
- **Decision:** All 7 files are documentation-only with zero behavioral dependencies. No test, source, or config files affected.
- **Rationale:** Confirmed: these are markdown instruction files. The only ordering constraint is AGENTS.md first (Task 1), then skills (Tasks 2-3) in any order.
- **Impact:** Tasks can proceed in parallel after Task 1 completes.

### Dimension: Edge Cases
- **Decision:** ast-grep supports only 25 programming languages — .md, .json, .yaml fall through to cocoindex/graphify/grep. The pipeline must account for this (included in decision table note).
- **Rationale:** Confirmed via ast-grep documentation and project experience.
- **Impact:** Added "Tool applicability note" to the AGENTS.md section.

### Dimension: Alternatives
- **Decision:** Three alternatives considered — (1) single hardcoded chain in AGENTS.md (rejected: doesn't account for non-linear use), (2) grep-only (rejected: higher token cost), (3) per-skill hardcoded lists (current approach, but inconsistent). Adopted: AGENTS.md as master anchor with cross-references.
- **Rationale:** Minimizes duplication while keeping the decision table in one place. Skills only keep guidance specific to their phase.
- **Impact:** Simpler maintenance — one source of truth for the decision framework.

### Dimension: Risks
- **Decision:** Three risks identified. Self-policing (no tech enforcement of hard gate — mitigation: exit declaration accountability), drift (7 files could desync — mitigation: AGENTS.md is anchor, skills cross-reference), completeness (might miss stale refs — mitigation: grep sweep in Code Discovery confirmed exact hit list).
- **Rationale:** All risks are acceptably mitigated. No behavioral blast radius.
- **Impact:** None block execution.

### Dimension: Consistency
- **Decision:** Standardize on "Smart Tool Selection" across all 7 files. Skill-specific headers to be renamed: "Smart scanning" → "Smart Tool Selection", "Smart Tools: Graphify + AST-Grep + Semantic Search" → "Smart Tool Selection", "Smart Tools" → "Smart Tool Selection", "Context Window Discipline" → "Smart Tool Selection".
- **Rationale:** One name for one concept reduces cognitive load. The header change in AGENTS.md (H3) requires updating 3 cross-references in DOCUMENT_GUIDELINES.md.
- **Impact:** Renaming work is mechanical but must be consistent.

### Dimension: Code Discovery
- **Decision:** Grep sweep across all .md files found 10 stale reference sites: AGENTS.md:110-113 (numbered list + duplicate 3.), 6 skill checklists (lines 22/28/23/26/21/26), 3 DOCUMENT_GUIDELINES.md references (lines 230, 394, 397). No stale references in source code, tests, or config files.
- **Rationale:** Direct grep was the appropriate tool for this task (keyword search across .md files — ast-grep doesn't support .md, cocoindex and graphify add no value for exact-string matching).
- **Impact:** Exact scope of work is known: 10 edits across 8 files.

### Dimension: Dependencies
- **Decision:** AGENTS.md is the master anchor — must be updated first (Task 1). The 6 skill files (Tasks 2-3) can proceed in any order after Task 1. DOCUMENT_GUIDELINES.md (Task 4) has no dependency on the other changes but is logically grouped.
- **Rationale:** The checklist fix (Task 2) and body rewrite (Task 3) both reference AGENTS.md §Smart Tool Selection, so the section must exist before those references are written. DOCUMENT_GUIDELINES.md is independent.
- **Impact:** Task ordering: 1 → 2+3 (parallel) → 4 (parallel with 2+3) → 5.
