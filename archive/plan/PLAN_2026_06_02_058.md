# PLAN_2026_06_02_048

## Problem Statement

After creating an event, the organizer currently only sees a QR code and "Join This Event" button. There is no way to configure which rooms/areas are available for the event or to set interest topics for participants. Additionally, there is no way to edit an existing event's configuration.

## Goals & Non-Goals

### Goals
- After event creation, show an "Organize Event" button that navigates to a new organize page
- Organize page lets organizers add/remove rooms (from defaults + custom) and topics (from defaults + custom)
- Rooms set on the organize page become the available rooms for participants on RoomPage
- Topics set on the organize page become available as "Interest" choices on the profile page
- Add "Edit an Event" section on HomePage for organizers to edit existing event config
- Rename "Join This Event" → "Test This Event" after event creation
- Block saving on organize page if rooms or topics lists are empty
- Save interests alongside profile in a single call

### Non-Goals
- No authentication/ownership for event editing (code-based access only, matching existing pattern)
- No pagination, search, or filtering of rooms/topics
- No analytics or logging of organizer actions
- No real-time sync of config changes to active participants
- No migration of existing events (new tables auto-created with defaults)

## Success Metrics

1. Organizer can create event, click "Organize Event", see 8 rooms and 6 topics pre-selected
2. Organizer can uncheck/add rooms and topics, save successfully
3. "Test This Event" navigates to profile form with interest multi-select showing configured topics
4. "Edit an Event" with valid code opens organizer page with existing config
5. Saving with empty rooms or topics shows validation error
6. All existing tests pass (backend + frontend + structural)

## Technical Approach

**Backend:** Add 2 new DB tables (`event_topics`, `user_interests`), 3 new API endpoints (`GET /api/events/{id}/config`, `PUT /api/events/{id}/config`, `GET /api/events/{id}/topics`), modify `create_event` to also insert default topics, modify `join_event` to accept optional `interests` field.

**Frontend:** New `OrganizeEventPage` with checkable room/topic lists and add/remove controls. Modify `HomePage` to show organize/edit buttons. Modify `UserInfoPage` to add interest multi-select using shadcn Command/Popover.

**Save strategy:** Single atomic `PUT /api/events/{id}/config` endpoint that updates both rooms and topics in one DB transaction. Interest saving bundled into the `POST /api/events/{id}/join` call.

### Architecture & Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Room/topic removal | Hard-delete + replace on save | Each event has isolated control; delete old set, insert new set in one transaction |
| Save endpoint | Single `PUT /api/events/{id}/config` | Atomic transaction prevents partial updates; aligns with eventual separation |
| Interests save | Bundled in `POST /api/events/{id}/join` | Single click UX — one save action for profile + interests |
| Empty save prevention | Frontend validation + backend validation | Blocks save if rooms or topics are empty |
| Invalid edit code | Navigate to page → 404 → error toast → redirect home | Same pattern as existing RoomPage error handling |
| Organize page UI | Checkbox lists with add/remove inline inputs | Clear visual hierarchy, matches mental model of "curating a set" |
| Interest selector | shadcn Command/Popover multi-select | Standard shadcn pattern, searchable, extensible |

## Open Questions & Risks

- **Race condition:** Organizer saves config while a participant is on RoomPage — participant may see stale list. Acceptable for MVP (no real-time sync).
- **Orphaned room references:** Hard-deleting rooms may leave stale `room_id` in users table for participants who already selected a removed room. Acceptable — SQLite FK not enforced by default, active participants keep room in memory.
- **Concurrent organizer edits:** Two organizers editing the same event — last save wins. Acceptable for MVP.
