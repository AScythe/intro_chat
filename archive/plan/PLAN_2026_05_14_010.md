# PLAN_2026_05_14_010

## Requirements / Problem

Standardize and improve workflow sections across the 6 update-* skill files. Each skill has a different document purpose and therefore a different workflow, but all share a common 5-step core pattern (`Investigate → Read → Identify → Update → Verify`). The analysis revealed 6 specific changes needed:

1. **"Ask the user" guidance** — only `update-agents` has it; 5 skills are missing this
2. **Session history review** — only `update-architecture` and `update-specifications` have it; 2 skills are missing
3. **Per-Function Detail Rules placement** — architecture's 55-line rules block sits orphaned between Content Rules and Workflow
4. **5-step mapping note** — best-practices' 2-phase structure lacks a note connecting it to the standard model
5. **Duplicate bullet** — readme's Update step has "Don't rewrite" appearing twice
6. **Boundary violations flag** — only readme's Read Current step checks for content boundary violations

## Solution

| # | Change | Skill(s) | Location |
|---|--------|----------|----------|
| A | Add "Ask the user" to Investigate (domain-customized) | architecture, best-practices, demo-guide, readme, specifications | End of Step 1 |
| B | Add session history review to Investigate | agents, readme | End of Step 1 |
| C | Move Per-Function Detail Rules into Workflow section | architecture | Replace lines 64-120 with cross-ref; insert after Step 1.75 |
| D | Add 5-step mapping note at top of Workflow | best-practices | After line 95 |
| E | Remove duplicate "Don't rewrite" bullet | readme | Line 112 |
| F | Add "Flag boundary violations" to Read Current | agents, architecture, demo-guide | Step 2 |

## Implementation Plan

### Approach & Design Decisions

1. **All changes are independent** — no file depends on another being modified first. Each file can be edited in any order.
2. **Domain-customization per skill** — every standardized item uses domain-appropriate language for its document type (e.g., "codebase" for architecture, "running app" for demo-guide).
3. **Preserve existing content** — no existing content is removed except the duplicate bullet in readme. The Per-Function Detail Rules are moved, not removed.
4. **Minimal diffs** — each change is a small insert, replace, or delete. No rewrites.

### Edge Cases

| Case | Resolution |
|------|------------|
| A skill already has the item being added | Check each file before editing — skip if already present |
| "Ask the user" wording conflicts with existing text nearby | Insert at the end of the Investigate step, separated by a blank line |
| Per-Function Rules cross-reference broken after move | Add `#175-extract-per-function-details` anchor; the heading `### 1.75 Extract Per-Function Details` already acts as anchor |
| best-practices mapping note placement | Insert after the existing workflow description line 95, before the `---` separator |

### Testing Strategy

Documentation-only changes. Verify by:
- Read each modified file to confirm accuracy
- grep for the standard first 4 Update bullets in all 6 files after changes (they should remain intact)
- Confirm no stale cross-references
