# PLAN_2026_06_02_052

## Problem Statement

Two bugs found in the organizer event flow:

1. **"Organize Event" button in wrong Card**: After creating an event on the home page, the "Organize Event" button renders in a separate `<Card>` below the `<QRDisplay>` card. It should be inside the same card for a cohesive UI.

2. **Room selection shows ALL rooms instead of configured ones**: When a test user joins an event and reaches the room selection page (`RoomPage`), the dropdown shows all 8 default rooms regardless of which rooms the organizer selected/deselected during event configuration. Deselected rooms (e.g., "Table 1") should not appear.

## Goals & Non-Goals

### Goals
- Move "Organize Event" button into the `QRDisplay` card component
- Filter `GET /api/events/{id}/rooms` to return only rooms with `selected = 1`
- All existing tests continue to pass

### Non-Goals
- No changes to how room configuration is saved or the chip UI
- No re-design of the home page layout beyond button placement
- No changes to room/topic creation or sample user fill logic

## Success Metrics

1. "Organize Event" button renders inside the QR code card, not as a separate card
2. Room select dropdown only lists rooms that were selected (saved) in the config
3. All 10 E2E tests, all backend tests, all 145 frontend unit tests pass
4. TypeScript type-check and frontend build succeed

## Technical Approach

### Issue 1 — Button placement in QRDisplay

Add an optional `onOrganize` callback prop to `QRDisplay`. Render the "Organize Event" button inside `CardContent` when the prop is provided. In `HomePage`, remove the separate `<Card>` wrapper and pass `onOrganize={() => navigate(...)}` directly to `QRDisplay`.

### Issue 2 — Room filtering by `selected`

Add `AND selected = 1` to the SQL query in:
- `helpers.py:get_rooms_for_event()` — primary query
- `routes_api.py:get_rooms()` — fallback query (uses `LOWER()` for case-insensitive matching)

Both currently fetch all rooms without filtering by the `selected` column.
