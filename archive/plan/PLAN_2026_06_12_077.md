# PLAN_2026_06_12_001

## Problem Statement

The user wants to delete three specific events from the database (IDs: `0ca2451e`, `c68cc13f`, `31884076`) with all associated data (rooms, users, matches, topics, interests). The existing `utility/cleanup_db.py` has `--keep-event` (keeps one, deletes all others) but no way to surgically delete specific events while leaving the rest intact.

## Goals & Non-Goals

### Goals
- Add `delete_events(cur, event_ids)` function to `utility/cleanup_db.py` that cascade-deletes specific events
- Add `--delete-events EID1 EID2 ...` CLI flag to invoke it
- Support combined mode: delete specified events, then run standard dedup/orphan cleanup
- Handle non-existent IDs gracefully (warn and skip)
- Idempotent — second run is a safe no-op

### Non-Goals
- No API endpoint changes — CLI tooling only
- No changes to test files — cascade pattern already tested via `cleanup_event()` in `test_app.py`
- No changes to frontend or application logic

## Success Metrics

1. `uv run python utility/cleanup_db.py --delete-events 0ca2451e c68cc13f 31884076` cascades all associated data for those 3 events
2. Running with non-existent IDs produces warnings but no crash
3. Second run is a safe no-op
4. Existing `--keep-event` behavior is unchanged
5. Both `--delete-events` and `--keep-event` can be combined (delete first, then keep)

## Technical Approach

Add a `delete_events(cur, event_ids)` function that follows the identical cascade pattern already used by `keep_only_event`, `dedup_events`, and `remove_orphaned_events`:

1. Separate `existing` from `not_found` IDs — warn for not_found, skip
2. Collect `room_ids` for the existing events
3. Delete `is_sample=1` users by room_id
4. Delete `user_interests` by event_id
5. Delete `matches` via subquery on users by event_id
6. Delete `users` by event_id
7. Delete `rooms` by event_id
8. Delete `event_topics` by event_id
9. Delete `events` by id
10. Print summary

Update `process()` to take `delete_event_ids` parameter and call `delete_events` before proceeding to `keep_only_event` / standard cleanup.

Update CLI arg parsing to collect space-separated IDs after `--delete-events`.
