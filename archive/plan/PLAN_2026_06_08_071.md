## Problem Statement

save-session is currently called from 5 skills: check-plan-readiness, implement-plan, review-implementation, modularize-and-clean, improve-architecture. User wants it only triggered during implementation/review phases, not planning. Also needs clarity on what content is captured during implementation.

## Goals & Non-Goals

### Goals

- Remove save-session write calls from planning-phase skills
- Keep save-session in implement-plan and review-implementation
- Document what content is captured during implementation sessions
- Keep continuity check (Phase 0 context recovery via header read) in all skills — it is read-only, not a session write

### Non-Goals

- No changes to save-session output format (user likes current format)
- No changes to continuity check mechanism
- No changes to AGENT_SETUP.md (save-session still exists as a skill)

## Technical Approach

Three batch changes followed by a doc note:

**Remove save-session phases** from check-plan-readiness, modularize-and-clean, improve-architecture. Each has a "Save Session" section and a Hand-off reference — both need removal.

**Update save-session** description and exit declaration to only list implement-plan and review-implementation.

**Add content note** in implement-plan Phase 4 documenting what specifically is captured during implementation (plan context, user instructions, agent actions, tool results, verification output).
