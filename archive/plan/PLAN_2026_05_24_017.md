# PLAN_001

## Problem Statement

The conversation timer was changed from 2 minutes to 30 seconds (`CONFIG.CHAT_DURATION: 30` in `frontend/src/config/constants.ts`), but all displayed text and documentation still say "2 minutes". The backend match expiry is also driven by `MATCH_EXPIRY_MINUTES = 2` (still 2 minutes), creating a mismatch between actual behavior and what users read.

## Goals & Non-Goals

### Goals
- All user-facing text dynamically reflects the actual `CHAT_DURATION` value
- Backend match expiry matches the conversation duration (also 30 seconds)
- All source-code references ("2 minutes") updated to the new config-driven approach
- Documentation updated to match the new behavior

### Non-Goals
- No changes to the cleanup threshold (`CLEANUP_THRESHOLD_SECONDS = 300`) — that's a hard limit for stale data removal, not the conversation window
- No changes to the timer hook (`useTimer.ts`), timer component (`Timer.tsx`), or matchmaking logic — only the config source and display strings
- No architectural rework — purely a config/text sync

## Success Metrics
- `MATCH_EXPIRY_SECONDS = 30` in config — consumed by `matchmaking.py` via `timedelta(seconds=MATCH_EXPIRY_SECONDS)`
- `ChatPage.tsx` shows "30 seconds" (or "1 minute 30 seconds" if `CHAT_DURATION` were changed) — no hardcoded "2 minutes" strings remain in source
- `test_state_constants` assertion updated and passing
- All three doc files (ARCHITECTURE.md, README.md, SPECIFICATIONS.md) reflect the new 30-second duration

## Technical Approach

### Backend: Rename and re-unit `MATCH_EXPIRY`
`app/config.py` currently uses `MATCH_EXPIRY_MINUTES = 2` with `timedelta(minutes=...)`. Rename to `MATCH_EXPIRY_SECONDS = 30` and use `timedelta(seconds=...)`. The `expires_at` column is informational only (never queried by enforcement), so this change is cosmetic for the backend — it makes the metadata accurate.

### Frontend: Dynamic display via `formatDuration`
Add a `formatDuration(seconds)` function to `frontend/src/utils/format.ts` that produces human-readable text with hybrid formatting (e.g., `30` → `"30 seconds"`, `90` → `"1 minute 30 seconds"`, `120` → `"2 minutes"`). Replace hardcoded "2 minutes" strings in `ChatPage.tsx` with `formatDuration(CONFIG.CHAT_DURATION)` calls.

### Documentation: Three files updated
`ARCHITECTURE.md` references `MATCH_EXPIRY_MINUTES` by name — update to `MATCH_EXPIRY_SECONDS`. `README.md` and `SPECIFICATIONS.md` replace "2 minutes" with the specific 30-second value.

### Architecture & Design Decisions

- **`MATCH_EXPIRY_MINUTES` → `MATCH_EXPIRY_SECONDS`**: Renaming avoids confusion with the unit change. Using `timedelta(minutes=0.5)` would be equally correct but less readable.
- **`formatDuration` in `format.ts`**: Co-located with existing `formatTime` utility. Named `formatDuration` to differentiate from `formatTime` (which returns `M:SS` format).
- **Hybrid formatting**: `30` → `"30 seconds"`, `120` → `"2 minutes"`, `90` → `"1 minute 30 seconds"`. Handles singular vs plural.
