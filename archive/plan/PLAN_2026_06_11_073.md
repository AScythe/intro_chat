# PLAN_2026_06_11_001

## Problem Statement

The `run-e2e-tests` skill is tightly coupled to this project — it hardcodes page names, app commands, database paths, and test scenarios specific to IntroChat. To be reusable across projects, it needs to be project-agnostic. Project-specific E2E details (test scenarios, webServer config, build commands) should live in a project-level doc that the skill generates by introspecting the project itself.

## Goals & Non-Goals

### Goals
- Make `run-e2e-tests` skill fully project-agnostic (zero hardcoded project-specific values)
- Rename to `generate-and-run-e2e-tests` to reflect dual purpose
- Skill auto-generates `docs/E2E_TESTING.md` by introspecting the project's Playwright config, spec files, and package.json
- Skill detects staleness via content hash and short-circuits to running tests when unchanged
- `docs/E2E_TESTING.md` has an auto-generated section + a manual section (user content carried forward across regenerations)
- All cross-references in AGENTS.md, ARCHITECTURE.md, tests, and other skills updated for rename

### Non-Goals
- No changes to Playwright test runner behavior
- No changes to existing spec files or test logic
- No changes to the Python or TypeScript source code

## Success Metrics

- Skill file contains zero references to specific app pages, commands, or paths
- Running the skill on this project generates a correct `docs/E2E_TESTING.md` with:
  - WebServer config, build command, baseURL extracted from playwright.config.ts
  - Test scenarios extracted from both `organizerFlow.spec.ts` and `participantFlow.spec.ts`
  - Package manager detected from lockfile
- Content hash correctly skips regeneration when spec files + config unchanged
- Manual content preserved across regenerations
- `npx playwright test` still passes
- All cross-references updated — `test_agent_guidelines.py` passes

## Technical Approach

### Architecture
The skill is refactored from a static instruction set into a multi-phase orchestrator:

```
Detection → Generation/Regeneration → Install → Build → Run → Report
```

The key innovation: the skill generates a project-specific document (`docs/E2E_TESTING.md`) that serves as both:
1. A persistent reference for developers
2. A cached configuration the skill reads on subsequent runs (short-circuit when unchanged)

### Doc Structure
`docs/E2E_TESTING.md` has two sections:
- **Auto-generated** (top) — scenarios table, webServer config, build command, content hash. Fully rewritten by the skill when regeneration triggers.
- **Manual** (bottom) — user notes, known issues, custom setup. Preserved and carried forward across regenerations.

### Regeneration Detection
- On each run, the skill computes a content hash (sha256) of the current Playwright config + spec file listing
- Compares against the stored hash in the doc
- Match → skip regeneration (run tests directly)
- Mismatch → regenerate the auto section

### Architecture & Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Skill name | `generate-and-run-e2e-tests` | Reflects dual purpose |
| Doc location | `docs/E2E_TESTING.md` | Follows `docs/` convention |
| Regeneration trigger | Content hash (sha256) of config + spec files | Robust to any change; git-independent |
| Doc structure | Auto + Manual sections | User edits preserved |
| Missing config | Generate minimal `playwright.config.ts` | Self-provisioning |
| Missing spec files | Empty table + notice | Graceful degradation |
| Package manager | Auto-detect via lockfile (npm/yarn/pnpm) | Cross-project compatible |
| Missing build command | Skip with notice | Works for no-build projects |
| Error strategy | Gen fail → stop+retry; install/build fail → stop; test fail → report | Clear boundaries |
