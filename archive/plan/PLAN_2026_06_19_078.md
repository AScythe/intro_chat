# PLAN_2026_06_19_001

## Problem Statement

The current agentic workflow has a structural gap: `implement-plan` Phase 1 (Setup) performs substantive codebase exploration (graphify, cocoindex, ast-grep) and batch mapping, but operates under a **read-only constraint on the plan file**. When exploration reveals gaps or inaccuracies in the plan, it cannot fix them — forcing an abort back to planning. This creates a wasteful loop where "ready" doesn't mean truly ready.

## Goals & Non-Goals

### Goals
- Move codebase validation and batch mapping from `implement-plan` into `check-plan-readiness`, where plan writes are permitted
- Make `check-plan-readiness` a substantive validation phase (not just presence-checking)
- Slim `implement-plan` Phase 1 to comprehension-only
- Ensure all skills maintain their existing hand-off interfaces (no downstream changes)

### Non-Goals
- No changes to `brainstorm-and-plan`, `grill-and-refine`, or any downstream skills
- No changes to `implement-plan` Phases 2-4 (TDD iteration, Verify, Save Session)
- No changes to `check-plan-readiness` Phases 1-2 (Gather, Create Document)
- No re-architecting of the 8 gates themselves — only Gate 8 becomes substantive

## Success Metrics

1. `check-plan-readiness` produces a plan with fully mapped batches (files, dependency order) appended to Task Breakdown
2. `implement-plan` Phase 1 contains no graphify, cocoindex, or ast-grep calls
3. All 8 gates pass against the finalized plan before hand-off
4. No breakage in any existing test or downstream skill

## Technical Approach

### Restructure check-plan-readiness

Add two new phases between document creation and gate verification:

| Phase | Current | New |
|-------|---------|-----|
| 1 | Gather from Conversation | Unchanged |
| 2 | Create Plan Document | Unchanged |
| **3** | *(skipped straight to gates)* | **Validate Against Codebase** — read ARCH.md, SPECS.md; run graphify query_graph, cocoindex-code_search, ast_grep_search. Compare task assumptions against actual code. Update plan if gaps found. |
| **4** | *(doesn't exist)* | **Map Batches** — translate Task Breakdown into exact files, dependency order. Append concrete batch sequence to plan doc. |
| 3→5 | Verify 8 Gates (presence) | Verify 8 Gates — now Gate 8 validated with real exploration data |
| 4→6 | Triage Failures | Unchanged |

### Slim implement-plan Phase 1

Remove Steps 3-4 (Codebase Exploration, Map Batches). Steps 1-2 become a single comprehension step: read plan, read relevant docs, ask clarifying questions. No graphify/cocoindex/ast-grep — those are now done upstream.

## Open Questions & Risks

- **Risk: Skill file drift** — if downstream skills reference specific phase numbers, they need updating. Mitigation: grep for references to Phase 1/Setup/Steps in other skill files after changes.
- **Risk: Gate 8 becomes too heavy** — adding graphify + cocoindex + ast-grep to check-plan-readiness could make it slow. Mitigation: this is acceptable — thoroughness before implementation prevents more costly re-plan loops.
- **Risk: implement-plan Phase 0 currently checks gates pass** — if Phase 1 exploration in the old flow could catch gate failures, the new flow must ensure check-plan-readiness catches them first. Mitigation: Gate 8 is now substantive, and Phase 3 Validate Against Codebase is designed specifically to surface gaps before "ready" is declared.

## Grill Outcomes

### Dimension: Where codebase exploration lives
- Decision: Move from implement-plan Phase 1 to check-plan-readiness as a new Phase 3 (Validate Against Codebase)
- Rationale: Exploration may reveal plan gaps; check-plan-readiness can write fixes, implement-plan cannot
- Impact: check-plan-readiness gains substantial new phase; implement-plan slims down

### Dimension: When batch mapping happens
- Decision: After codebase validation, before gates — linear flow (validate → map → gate-check)
- Rationale: Mapping may reveal gaps that gates should catch; gates need real data for Gate 8
- Impact: New Phase 4 in check-plan-readiness

### Dimension: implement-plan Phase 1 scope
- Decision: Comprehension-only (read docs, read plan, ask clarifying questions)
- Rationale: All substantive exploration moved upstream; implementer only needs to understand the pre-verified plan
- Impact: implement-plan Phase 1 shrinks from 4 steps to 1-2
