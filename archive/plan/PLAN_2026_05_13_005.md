# PLAN_2026_05_13_005

## Requirements / Problem

Convert the existing vanilla JS + Jinja2 HTML frontend into a modular, maintainable React SPA with TypeScript (TSX/JSX). The current frontend consists of:

- **4 Jinja2 HTML templates** (118 + 68 + 109 + 121 = 416 lines) served by FastAPI
- **9 vanilla JS files** (1,545 lines) using global-scope functions, no modules
- **1 CSS file** (898 lines)
- **No build tools, no package.json, no React, no TypeScript**

The conversion must:
1. Adopt React with React Router (full SPA)
2. Use TypeScript throughout (all `.tsx`/`.ts`)
3. Live in a separate `frontend/` directory with its own build pipeline
4. Keep the existing FastAPI backend (REST + WebSocket endpoints unchanged)
5. Preserve the existing `style.css` with identical class names (zero visual regression)
6. Keep and cleanly refactor demo/simulation mode into a feature-flagged hook
7. Maintain existing functionality: event creation, QR codes, room selection, matchmaking, timed chat, chat extensions, Slack connection exchange

## Solution

Build a React SPA using Vite + TypeScript in a new `frontend/` directory. The SPA handles all routing client-side via React Router. The FastAPI backend is simplified to serve the SPA's built output as a catch-all route while keeping all REST and WebSocket endpoints unchanged.

### Architecture

```
Browser ──GET /──→ FastAPI (catch-all) ──→ frontend/dist/index.html
Browser ──GET /api/*──→ FastAPI (REST) ──→ JSON responses
Browser ──WS /ws──→ FastAPI (WebSocket) ──→ real-time events
```

### Approach & Design Decisions

1. **Vite over CRA** — faster builds, native TypeScript support, Vitest integration
2. **React Context over Redux/Zustand** — app has 2-3 shared state slices (user session, socket, timer); Context is sufficient and avoids extra dependencies
3. **Same CSS class names** — `style.css` imported at `main.tsx` root; all React components reuse existing classNames (`.card`, `.btn-primary`, `.timer`, etc.) for zero visual regression
4. **Feature flag for demo** — `useDemoMode()` hook wrapped behind `import.meta.env.VITE_ENABLE_DEMO` env variable; demo logic compiles out in production builds
5. **Single persistent WebSocket** — `SocketContext` connects at app root, stores connection in context, auto-reconnects on disconnect; all pages consume via `useSocket()` hook
6. **Route param data instead of `window` globals** — `window.chatMatchId`, `window.roomEventId`, etc. become React Router `useParams()` values
7. **localStorage as persistence layer** — user ID, event ID still stored in localStorage; `UserContext` hydrates on app init and writes on change

### Edge Cases

| Edge Case | Handling |
|-----------|----------|
| **Demo mode mixed with real logic** | Extract all `setTimeout` simulations + hardcoded responses into `useDemoMode.ts`. The hook returns `{ isDemo, simulateResponse, delay }` and is gated by `VITE_ENABLE_DEMO`. Room/Chat pages check `isDemo` before branching. |
| **WS reconnect on temporary network loss** | `SocketContext` implements exponential backoff reconnect (1s, 2s, 4s, 8s max). Stores pending messages and replays on reconnect. |
| **SPA navigation during WS message handling** | All WS message handlers dispatch to Zustand-less Context setters that persist across route changes. No message loss on navigation. |
| **Page refresh in SPA** | User session (userId, eventId) persisted in localStorage. `UserContext` rehydrates on app mount. All other state starts fresh. |
| **Browser back/forward navigation** | React Router handles history. No special handling needed — each page re-fetches data via API on mount. |
| **QR base64 image rendering** | Direct `<img src={base64Data} />` — same as current HTML. |
| **60s countdown → `/chat/:matchId`** | `navigate()` replaces `window.location.href`. Countdown uses `useTimer` hook. |
| **Timer multi-instance (chat timer + extended timer)** | `useTimer` returns fresh `{ start, clear, getTimeLeft, extend }` per call. Parent component orchestrates switching. |
