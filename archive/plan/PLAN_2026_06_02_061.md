# PLAN_2026_06_02_051

## Problem Statement

1. **UI placement**: "Test This Event" button lives inside the post-creation QR card, only visible right after creating an event. Users who already created an event and navigated away cannot find it. It should be under "Edit an Event" section, disabled until an event code is entered.

2. **Bug: rooms/topics empty on edit**: When entering an event code in "Edit an Event" and clicking "Edit Event", the `handleEdit()` function uppercases the code (`41682ae1` → `41682AE1`). The `GET /api/events/{id}/config` endpoint uses exact (case-sensitive) SQL matching, so `41682AE1` doesn't match the stored `41682ae1` → 404 → redirect to home. Rooms/topics appear "empty" briefly before redirect.

3. **E2E coverage**: The existing organizer flow tests are incomplete — they don't cover the full round-trip: create → configure → re-edit → test event → full user flow.

## Goals & Non-Goals

### Goals
- Move "Test This Event" button under "Edit an Event" card, disabled until event code entered
- Fix case-sensitivity bug causing rooms/topics to appear empty on edit
- Rewrite organizerFlow E2E tests to cover the full round-trip flow
- All existing tests continue to pass

### Non-Goals
- No changes to the join flow or `handleJoin` (it works via `LOWER()` queries)
- No changes to the user-facing appearance of the organize page
- No changes to DB schema

## Technical Approach

### Bug Fix: Case-Insensitive Event ID Matching

Two-part fix:
1. **Frontend**: Remove `.toUpperCase()` from `handleEdit()` in `HomePage.tsx` — event IDs are lowercase hex from `short_id()`, uppercasing destroys the match.
2. **Backend**: Use `LOWER(event_id) = LOWER(?)` in `get_event_config` and `save_event_config` for all event_id queries, consistent with the existing `get_rooms` endpoint.

### UI Change: Move "Test This Event" Button

- Remove the "Test This Event" button and its wrapping Card from the `createdEvent` section (lines 123-133 of HomePage.tsx)
- Add a "Test This Event" button inside the "Edit an Event" card, alongside the existing "Edit Event" button
- Both buttons share the `editCode` state
- Both disabled when `editCode.trim().length !== 8`
- "Test This Event" navigates to `/join/{editCode}`

### E2E Test Pattern

Replace `organizerFlow.spec.ts` with a single comprehensive test covering:
1. Create event (API), open organize page via event code input → configure (deselect some defaults, add custom room/topic) → save → verify home redirect
2. Enter same code → edit → verify state persisted → remove 1 default room + 1 default topic → save again → verify home redirect
3. Enter code → click "Test This Event" → fill profile → select room → PeoplePage → demo match → chat → back home

### Architecture & Design Decisions

- **Shared state**: The "Test This Event" button reuses the existing `editCode` state from the "Edit an Event" card. No new state variables needed.
- **Case-insensitive backend**: Using `LOWER()` in SQL is the defensive choice — it handles any frontend case handling, past or future.
- **Two buttons, one row**: "Edit Event" and "Test This Event" sit side-by-side in a `flex gap-2` layout below the input.
