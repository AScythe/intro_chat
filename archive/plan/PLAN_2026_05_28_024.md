# PLAN_2026_05_28_002

## Problem Statement

After every code change (implement-plan, improve-architecture, modularize-and-clean), the CocoIndex semantic search index and Graphify knowledge graph become stale. When `review-implementation` queries these tools for verification, it gets **pre-change data** — defeating the purpose of verification.

Currently there is no automated step to rebuild them. The commands exist in the Commands Reference (`ccc index`, `graphify .`) but there is no process-level instruction about when to run them.

## Goals & Non-Goals

### Goals
- Auto-detect whether source files changed (vs. docs/configs only)
- If changed: rebuild CocoIndex code index and Graphify knowledge graph before review verification
- If unchanged: skip rebuild with clear message
- Non-blocking on failure — warn but continue review
- Handle edge cases: first-time setup, missing tools, timeouts

### Non-Goals
- Rebuilding during implementation phases (only during review)
- Git hooks for rebuilds
- Changing the SDD phase ordering
- Rebuilding on every review invocation unconditionally

## Success Metrics

- Necessity check correctly identifies source-only changes vs. docs-only changes
- `ccc index` and `graphify .` run only when source files changed
- Failures produce clear warnings but don't block the review
- No new tooling dependencies introduced

## Technical Approach

Create a dedicated **`rebuild-indexes`** utility skill (Build mode) that contains all rebuild logic:
1. Check `git diff --name-only $(git merge-base HEAD main) HEAD` for changed files
2. Filter to indexed file types
3. Conditionally rebuild CocoIndex and Graphify
4. Handle timeouts, missing tools, and first-time setup

The `review-implementation` skill (Plan mode) loads `rebuild-indexes` as a Phase 0 prerequisite before baseline tests. This keeps the rebuild logic reusable and independently invocable.

### Architecture & Design Decisions

- **Skill location**: `.opencode/skills/rebuild-indexes/` — follows existing skill convention
- **Mode**: Build (runs CLI commands — `ccc`, `graphify`, `git`)
- **Necessity detection**: Filter `git diff` output against indexed extensions: `.py`, `.ts`, `.tsx`, `.js`, `.jsx`, `.css`, `.json`, `.html`, `.toml`
- **Git diff base**: `$(git merge-base HEAD main)` — captures all changes since branch off main
- **Command not found**: Warn once and continue
- **Missing settings.yml**: Auto-init: `ccc init && ccc index`
- **Timeout**: 120s per rebuild command, warn and continue on timeout
- **Failure behavior**: Non-blocking — log WARNING, continue review

## Grill Outcomes

### Dimension: Assumptions
- Decision: Use comprehensive file-type list for necessity detection `.py`, `.ts`, `.tsx`, `.js`, `.jsx`, `.css`, `.json`, `.html`, `.toml`
- Rationale: CocoIndex indexes all these types (verified via `ccc status` output)
- Impact: Rebuild triggers on any indexed-file-type change, not just "code" files

### Dimension: Edge Cases
- Decision: Diff against `git merge-base HEAD main`; warn on missing CLI; auto-init `ccc init`; 120s timeout per command; warn-and-continue on failure
- Rationale: Robustness against missing tools, fresh clones, and long rebuilds
- Impact: Rebuild step never blocks review; always warns clearly on problems

### Dimension: Alternatives
- Decision: Dedicated `rebuild-indexes` utility skill (not inline in review-implementation)
- Rationale: Reusable across contexts, independently invocable, single source of truth
- Impact: One additional skill file to create; clean separation of concerns

### Dimension: Dependencies
- Decision: No new dependencies — `ccc`, `graphify`, and `git` are already project requirements
- Rationale: Verified against AGENT_SETUP.md
- Impact: No installation or env changes needed

### Dimension: Risks
- Decision: Low risk — necessity check prevents unnecessary rebuilds; timeout prevents hangs; failure is non-blocking
- Rationale: Mitigations cover all identified risks
- Impact: Proceed with plan as designed

### Dimension: Consistency
- Decision: No changes to SDD phase ordering; rebuild-indexes is a utility invoked from Phase 0
- Rationale: Fits existing pattern (skills define workflows, agents execute them)
- Impact: No structural changes to existing skills

### Dimension: Code Discovery
- Decision: `ccc` available and index built; `graphify` not available on this machine (validation done via docs); both commands are documented in AGENT_SETUP.md
- Rationale: Sufficient info to proceed
- Impact: No blockers
