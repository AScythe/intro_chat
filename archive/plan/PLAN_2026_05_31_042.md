# PLAN_2026_05_31_042

## Problem Statement

Two needs have emerged from this session:

1. **Workflow formalization**: The user always runs `improve-architecture` and `modularize-and-clean` together in parallel, with a single unified plan document produced before implementation. This pattern is not currently documented — neither skill references the other, and AGENTS.md has no rule for combined parallel execution.

2. **Code quality**: The codebase has accumulated structural issues — a thread-safety data race in shared state, non-idempotent match creation, missing type hints, import ordering violations, duplicated logic, large frontend pages, and test coverage gaps.

## Goals & Non-Goals

### Architecture & Design Decisions

1. **Lock granularity**: Single dedicated `threading.Lock` for `active_matches` only (not the other 3 shared dicts) — avoids unnecessary contention on non-thread-crossing state.
2. **Idempotency approach**: App-level check in `create_match()` rather than DB UNIQUE constraint — test explicitly creates duplicate pair for connection-declined path.
3. **Logging left alone**: Project standard (`implement-plan/SKILL.md`) requires per-file `logging.basicConfig()` — the "DRY violation" is intentional convention.
4. **Sub-view extraction**: Views stay as pure props components (no internal hooks) to keep them testable and reusable.

- **Full suite**: After all batches, run `uv run python tests/test_app.py && uv run python tests/test_js_modules.py && uv run python tests/test_db.py && uv run python tests/test_agent_guidelines.py` (backend) + `cd frontend; npm test; npx tsc --noEmit; npm run build` (frontend)
- **New tests**: Batch 7 adds direct unit tests for previously untested modules — these are additive, not modifying existing tests
