# PLAN_2026_05_31_043

## Problem Statement

We need a mechanism to auto-save session conversations at key workflow transition points, preserving user↔agent exchanges (excluding `thinking` blocks) as formatted timeline files. Separately, archived plan documents need to be organized under `archive/plan/` to match the emerging archive structure pattern alongside `archive/skills/` and `archive/sessions/`.

## Goals & Non-Goals

### Goals

- Create a `save-session` skill that writes session conversations to `docs/sessions/SESSION_YYYY_MM_DD_NNN.md`
- Save at two trigger points: after `check-plan-readiness`, after `review-implementation`
- Use incremental append with a meta tracking file (`.SESSION_*.meta`) for dedup
- Exclude `thinking` blocks and compaction summaries
- Truncate tool results to ~10 lines
- Maintain max 3 session files in `docs/sessions/` — oldest auto-archived to `archive/sessions/`
- Migrate existing `archive/PLAN_*.md` → `archive/plan/PLAN_*.md`
- Update all 7 reference files to reflect the new `archive/plan/` path

### Non-Goals

- No real-time background saving (agent cannot hook into system events)
- No restoration of context from session files (archival only)
- No modification to the `implement-plan` skill itself
- No JSON/YAML format alternative

## Success Metrics

1. `docs/sessions/SESSION_*.md` created after check-plan-readiness
2. Same file appended (not duplicated) after review-implementation
3. Zero `thinking` blocks in session file (verified via grep)
4. Tool results truncated (~10 lines max)
5. 4th session file triggers archival of oldest to `archive/sessions/`
6. `archive/plan/` exists with all migrated plan files
7. All 7 reference paths updated

## Technical Approach

### Save-Session Skill

A utility skill in `.opencode/skills/save-session/SKILL.md` that:

1. **Determines session file**: Scans `docs/sessions/` + `archive/sessions/` for highest global NNN → new file or append
2. **Gate**: Asks user — start fresh file or continue? Default: per-plan = new file
3. **Reads conversation**: From agent context, filters `thinking` blocks, compaction summaries
4. **Formats timeline**: `## User YYYY-MM-DD HH:MM` / `## Assistant YYYY-MM-DD HH:MM` / `[Tool: name] truncated output`
5. **Writes/Appends**: Creates directory + file if new; reads `.SESSION_*.meta` for last-saved position for append
6. **Rotation**: If `docs/sessions/` has ≥3 `SESSION_*.md` files, moves oldest to `archive/sessions/`

### Plan Archive Path Migration

Change `review-implementation/SKILL.md` lines 34, 169–176: `archive/PLAN_*.md` → `archive/plan/PLAN_*.md`. One-time migration of existing 39 files.

### Architecture & Design Decisions

- Meta tracking file (`.SESSION_*.meta`) stores last-saved message position — ensures idempotent append
- Session file format is plain Markdown with `## User` / `## Assistant` / `[Tool: name]` section headers
- Global sequential NNN (like plans) — scans `docs/sessions/` + `archive/sessions/`
- Strict/blocking save — on failure, report error and stop (but retryable)
- Plan migration is a one-time bulk move; path references updated everywhere
- ``.ignore`` excludes `docs/sessions/` from OpenCode watching (same pattern as `archive/`)

## Open Questions & Risks

| Risk | Mitigation |
|------|------------|
| Context loss during long single-phase conversations | Manual "save session" fallback |
| File system errors (permission, disk) | Block + retry; idempotent operation |
| NNN collision with archived session | Scan both `docs/sessions/` + `archive/sessions/` |
| Migration of 39 plan files conflicts | Idempotent: only move files not already under `archive/plan/` |
