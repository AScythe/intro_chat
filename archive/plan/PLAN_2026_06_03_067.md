# PLAN_2026_06_03_067

## Problem Statement

`update-docs` has only a single mode — full-scan, user-review-heavy. It should have two modes (explicit/implicit) mirroring `rebuild-test-and-indexes`. `review-implementation` suggests `update-docs` in its Exit Declaration but doesn't auto-call it — the user must manually invoke it after review. This breaks the "automatic final step" pattern established by `rebuild-test-and-indexes`.

## Goals & Non-Goals

### Goals
- Dual-mode (explicit + implicit) for `update-docs`, matching `rebuild-test-and-indexes` pattern
- `review-implementation` auto-calls `update-docs` implicit after successful sign-off
- Implicit mode: git diff delta → sub-agents (graphify context, delta proposals) → quick approval per doc → apply → verify cross-references
- Explicit mode: unchanged current behavior (full scan, per-doc review, apply, verify)
- `AGENTS.md` utility skills entry updated to describe dual mode

### Non-Goals
- No behavioral changes to doc update sub-skills (update-architecture-md etc.) — only how they're invoked
- No code changes — skill files and AGENTS.md only
- No changes to `rebuild-test-and-indexes` or `save-session`

## Technical Approach

### Architecture

`update-docs` gets an explicit/implicit split identical in concept to `rebuild-test-and-indexes`:

| Aspect | Explicit (standalone) | Implicit (Phase 3 of review-implementation) |
|--------|----------------------|----------------------------------------------|
| Detection | Full codebase + session history | git diff delta |
| Scope | ALL docs — full analysis | Only docs matching changed files |
| Investigation | Full: graphify + codebase walk + session | Light: graphify for context, skip full codebase walk |
| Proposal | Full per-doc proposals | Delta-only proposals |
| Approval | Serial per-doc review (full diff display) | Quick summary per doc (question tool) |
| Apply | After approval per doc | After quick approval per doc |
| Verify | Cross-reference integrity | Cross-reference integrity (always runs) |
| Blocking | Yes — user must complete review | Non-blocking — failures warn but don't halt caller |

### Key Design Decisions

1. **Parent-level filtering:** `update-docs` determines scope (git diff → triggers), passes `mode="implicit"` flag to sub-skills. Sub-skills don't each need their own dual mode.

2. **Sub-skill delta behavior:** In implicit mode, sub-skills still run `graphify query_graph` for context but skip full codebase walk. They only return proposals related to diff files.

3. **Quick approval per doc:** Implicit mode doesn't fully auto-apply — it shows a per-doc summary ("Architecture: 3 entries updated") and asks for quick approval via `question` tool. Lighter than full review, less risky than blind auto-apply.

4. **Cross-reference verification always runs:** Even on empty diff or no triggers matched — maintains integrity.

5. **Non-blocking:** Implicit mode failures produce warnings but don't halt `review-implementation`. Docs sync errors are informational, not fatal.

6. **Integration after save-session:** `update-docs` implicit runs after plan archive + session save, before hand-off. Docs sync is the last automated step before the agent declares success.
