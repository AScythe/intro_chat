# PLAN_2026_05_31_001

## Problem Statement

Three user-facing bugs in the frontend:

1. **Wrong name in chat header** — When a user selects a person in a room and proceeds through the demo match flow, the chat header always shows "Chatting with Dan_DevOps" instead of the selected person's name. Root cause: `PeoplePage.handleGoToChat()` uses `demo.createDemoMatchId()` generating a `demo_`-prefixed ID, and `ChatPage.loadMatchInfo()` hardcodes `'Dan_DevOps'` for all demo matches.

2. **Button styling mismatch** — In the "Time's Up!" view, "Extend for 30 seconds" uses default primary variant while "Continue indefinitely" uses `variant="outline"`. User wants same CTA level/color.

3. **Profile save stuck on "Saving..."** — In `UserInfoPage.handleSave()`, `setSaving(false)` is never called on the success path.

## Goals & Non-Goals

### Goals
- Chat header displays the actual person the user selected, not "Dan_DevOps"
- "Continue indefinitely" button has same visual style as "Extend for 30 seconds"
- Profile save button resets to "Save Profile" after successful save
- Backward compatible: all existing tests pass

### Non-Goals
- No real WebSocket/matchmaking changes
- No backend API changes
- No new dependencies

## Success Metrics

- Selecting "Sarah_Dev" → chat header shows "Chatting with Sarah_Dev"
- No `partner` URL param → fallback to "Dan_DevOps" (backward compatible)
- Both extend buttons appear visually identical
- Profile save completes → button reads "Save Profile"
- All 92 existing tests pass; new tests cover partner name param

## Technical Approach

### Fix 1: Partner name via URL param
Pass name from PeoplePage to ChatPage via `&partner=` URL search param. ChatPage reads it with fallback to `'Dan_DevOps'`.

### Fix 2: Remove `variant="outline"`
Remove `variant="outline"` from "Continue indefinitely" — defaults to primary, matching the other button.

### Fix 3: Add missing `setSaving(false)`
Add `setSaving(false)` after the successful save block in UserInfoPage.handleSave().
