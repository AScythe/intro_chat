# PLAN_2026_05_31_037

## Problem Statement

AGENTS.md has 12 major sections with ~250 lines of rules, policies, and references. Currently, only 2 sections (Skill Routing, Tool Selection) are validated by `tests/test_agent_guidelines.py`. The remaining 10 sections contain verifiable claims — file paths, command targets, documentation references, naming conventions — that can drift from reality without detection. We need structural integrity tests for every verifiable claim in AGENTS.md.

## Goals & Non-Goals

### Goals
- Validate every **file path** in the File Ownership table (lines 133–158) exists on disk
- Validate every **command target** in the Commands Reference (lines 175–188) has its prerequisites on disk
- Validate every **doc path** in Documentation Structure (lines 221–234) exists
- Validate **naming conventions** in Test Suite Structure (lines 192–207) match actual files
- Validate **utility skill references** (lines 211–217) exist on disk
- Validate **description headers** on all source code files per Documentation Discipline (line 241)
- Validate **tool availability** (uv, npm) per Tooling Rules (lines 247–250)
- Follow exact same test pattern as existing functions: `check()` helper, `PASS`/`FAIL` counters, emoji output

### Non-Goals
- No validation of behavioral rules (Process Discipline, Failure Triage, Key Ordering — these are agent instructions, not verifiable claims)
- No link anchor resolution (skip internal `#anchor` verification)
- No re-testing of what's already covered (skill routing, tool selection, priority chain)
- No test double or mocking — all validations are static filesystem checks

## Technical Approach

Extend `tests/test_agent_guidelines.py` with 7 new test functions, each mapping to one AGENTS.md section. Use Python stdlib exclusively — `os.path`, `os.walk`, `subprocess` for tool checks. Follow the existing `check()` / `PASS`/`FAIL` / `main()` pattern.

## Implementation Plan

### Files to Create, Modify, or Remove

- **Modify:** `tests/test_agent_guidelines.py` — add 7 test functions (no changes to existing)

### Architecture & Design Decisions

- **Auto-generated paths** (`data/*.db`, `.cocoindex_code`, `graphify-out`): soft-warn via `print('⚠️ ...')` — these are created at runtime/tool-build time, not source files
- **`frontend/node_modules/`**: hard fail if missing (hard prerequisite)
- **Description headers**: full scan via Python `os.walk`, all `.py` + `.ts` + `.tsx` files in `app/` and `frontend/src/`
- **Links**: skip validation entirely
- **PLAN_*.md / archive/PLAN_*.md**: check parent dir exists; pattern-matching on files is flexible (transitory files)
- **Test functions** will exactly mirror existing pattern: `def test_*():` with `print()` headers and `check()` assertions

### Testing Strategy

No new test suite — these ARE the tests. Verify by running:
```bash
uv run python tests/test_agent_guidelines.py
```
And:
```bash
uv run python tests/test_app.py
cd frontend ; npm test
cd frontend ; npx tsc --noEmit
```
