# PLAN_2026_06_09_001

## Problem Statement

The database has 288 events but only 7 distinct names — all from repeated test runs without cleanup. This causes data bloat (2304 rooms, 1002 room_sample_users, 330 users) and makes the database slow and cluttered. Additionally, no UNIQUE constraints exist to prevent future duplicates, and tests reuse the live database without cleaning up.

## Goals & Non-Goals

### Goals
- Cascade-delete duplicate-named events (keep earliest), removing all associated child data
- Add UNIQUE constraints on `events(name)` and `room_sample_users(room_id, user_name)`
- Add name-conflict check in `POST /api/events` returning `409 Conflict`
- Add test cleanup so tests delete their events after running

### Non-Goals
- Not fixing the race condition in concurrent config saves (pre-existing, out of scope)
- Not migrating to a test-specific database file (tests will clean up after themselves instead)

## Success Metrics

- 288 events → 7 events (one per distinct name)
- Child tables (rooms, users, matches, etc.) proportionally cleaned
- `CREATE UNIQUE INDEX` on `events(name)` prevents new duplicate names
- `POST /api/events` with existing name returns 409
- Tests can run without leaving duplicate events

## Technical Approach

**Cascade delete** each duplicate event in topological order (child tables before parent), wrapped in a single SQLite transaction. Replace the old `dedup_events()` merge logic in `utility/cleanup_db.py` with the new cascade version. Then add schema-level UNIQUE indexes and application-level conflict handling.

### Architecture & Design Decisions

- Keep earliest event by `created_at` (`COALESCE(created_at, '1970-01-01')` for NULL-safe sorting)
- Cascade order: room_sample_users → matches → user_interests → users → rooms → event_topics → events
- All steps wrapped in a single transaction (rollback on any failure)
- Replace (not append) the old `dedup_events()` — one clean approach
- Phase 2 UNIQUE index on `events(name)` requires unique names — so cleanup must run first

### Testing Strategy

2. Verify `POST /api/events` with existing name returns 409 after Phase 2
3. Run full test suite after all changes, verify no regressions

## Open Questions & Risks

- **Data loss risk:** All users in deleted events are removed. Confirmed with user — acceptable since these are test events.
- **Transaction safety:** Entire cascade in one transaction. If interrupted, rollback leaves DB unchanged.
- **NULL created_at:** Handled via COALESCE, treats NULL as epoch start (oldest).
