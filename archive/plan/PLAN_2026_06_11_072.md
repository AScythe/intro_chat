# PLAN_2026_06_11_001

## Problem Statement

Current agent skills (implement-plan, review-implementation, modularize-and-clean, improve-architecture) cover Code Quality, Documentation, and Testing well, but leave significant gaps in Security, Performance, Config/Dependencies, PR-Level concerns, and Logic/Correctness. We need to:

1. Refine the 4 existing skills to improve partial/minimal coverage
2. Create a new `improve-security` skill (following the `improve-*` template)
3. Improve logic & correctness coverage through enhanced test practices

## Goals & Non-Goals

### Goals
- New `improve-security` skill with 9 scan dimensions and `[SECURITY]` flags
- `implement-plan` refinements: concrete performance audit checks, structured dependency audit, Edge Case First TDD principle
- `review-implementation` refinements: `[SECURITY]` flag routing, PR size heuristic + commit message scan, config file diff check, edge case coverage audit + happy-path-only anti-pattern
- `modularize-and-clean` + `improve-architecture` combined execution sections extended to include `improve-security`
- Default combined execution flow: all 3 skills (modularize-and-clean + improve-architecture + improve-security) run together after first-pass review
- AGENTS.md and test_agent_guidelines.py updated for new skill

### Non-Goals
- No changes to `modularize-and-clean`'s 11 scan scopes (already sufficient)
- No changes to `improve-architecture`'s 8 scan areas (only combined execution text)
- No logic/correctness automated checker (remains test-based)
- No dependency vulnerability scanning with external tools (CVEs out of scope)

## Success Metrics

- All 8 gates pass for this plan document

- Combined execution of all 3 skills is the default flow

## Technical Approach

### Architecture

```
implement-plan ──→ review-implementation (first pass)
                        │
                        ▼ (default: combined)
            ┌───────────┼───────────┐
            ▼           ▼           ▼
   modularize-and-  improve-    improve-
   clean           architecture  security
            │           │           │
            └───────────┼───────────┘
                        ▼ (parallel Phase 1 → unified plan doc → apply batches)
               review-implementation (combined multi-flag pass)
```

### Flag Convention

| Flag | Skill |
|------|-------|
| `[ADDED]` `[MODIFIED]` `[FIXED]` `[REMOVED]` `[MOVED]` | implement-plan |
| `[CLEANUP]` | modularize-and-clean |
| `[ARCH]` | improve-architecture |
| `[SECURITY]` | improve-security (new) |

Flags are never mixed within a single batch, but different batches in a combined execution may carry different flags.

### review-implementation Phase 1 Step 1 — New Pass Type Table

| Flag type(s) | Pass | Prior skill(s) |
|--------------|------|----------------|
| `[ADDED]` `[MODIFIED]` `[FIXED]` `[REMOVED]` `[MOVED]` | First pass | implement-plan |
| `[CLEANUP]` only | Clean-up pass | modularize-and-clean |
| `[ARCH]` only | Architecture pass | improve-architecture |
| `[SECURITY]` only | Security pass | improve-security |
| `[CLEANUP]` + `[ARCH]` | Combined CA pass | modularize-and-clean + improve-architecture |
| `[CLEANUP]` + `[SECURITY]` | Combined CS pass | modularize-and-clean + improve-security |
| `[ARCH]` + `[SECURITY]` | Combined AS pass | improve-architecture + improve-security |
| `[CLEANUP]` + `[ARCH]` + `[SECURITY]` | Combined triple pass | All three |

Any flag not matching the pass type → route back to the offending skill.

### Architecture & Design Decisions

**improve-security skill structure** — mirrors improve-architecture:
- Phase 1 (read-only): Scan 9 security dimensions (secrets, unsafe deserialization, SQL injection, XSS, input validation, CORS, secure config, WS security, rate limiting)
- Gate: User approval via question tool
- Phase 1.5: Plan document at docs/PLAN_*.md
- Phase 2: Apply with [SECURITY] flags, TDD oracle approach
- Phase 3: Verify (tests, lint)
- Phase 4: Save session
- Phase 5: Update docs
- Combined execution section as primary flow

**Combined execution as default** — in review-implementation's exit declaration, all 3 skills are offered together. Each skill's combined execution section is the primary workflow (not a sub-section).

**Logic/correctness — dual mechanism:**
- implement-plan: "Edge Case First" guiding principle — enumerate boundaries before writing body, each test covers at least one boundary condition
- review-implementation: "happy-path-only" anti-pattern detection in Phase 3 Step 1 — flag when all tests pass on success with none testing failure modes

## Open Questions & Risks

- **Risk: Skill file size growth** — review-implementation is already large. Adding pass type table + PR checks + edge case audit + exit declarations may push it over 200 lines. Mitigation: keep edits surgical, use concise language.
- **Risk: Combined execution complexity** — 3 skills running parallel Phase 1 produces a large unified plan doc. This already works for 2 skills (architecture + cleanup), extending to 3 is additive.
- **Risk: Flag routing edge case** — what if a combined pass has [CLEANUP] + [ARCH] + [SECURITY] but also a bare [MODIFIED] (from missed code change)? The "any non-matching flag" rule correctly routes back. This is the desired behavior.
