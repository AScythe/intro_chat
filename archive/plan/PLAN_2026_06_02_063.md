# PLAN_2026_06_02_053

## Problem Statement

Interest/topic selection on the user profile page (`UserInfoPage`) shows **all** default topics regardless of which topics the organizer selected/deselected during event configuration. Topics deselected by the organizer (e.g., "DevOps") still appear in the user's interest combobox.

## Goals & Non-Goals

### Goals
- `GET /api/events/{event_id}/topics` returns only topics with `selected = 1`
- E2E test verifies deselected topics do not appear in the interest dropdown

### Non-Goals
- No changes to how topics are saved or the config UI
- No changes to room filtering (already fixed)

## Success Metrics

1. User interest combobox only shows topics that were selected (saved) in config
2. E2E Test 3: "DevOps" (deselected) not visible, "AI Development" (kept) visible
3. All 147 frontend unit tests, all backend tests, all 10 E2E tests pass
4. TypeScript type-check and frontend build succeed

## Technical Approach

### Root Cause

The `get_event_topics` endpoint in `routes_api.py:195` queries:
```sql
SELECT id, name FROM event_topics WHERE event_id = ?
```
This returns all topics regardless of the `selected` column. The `selected` column already exists and is correctly maintained by the `save_config` endpoint — the query simply wasn't filtering on it.

### Fix

Add `AND selected = 1` to the SQL query in the `get_event_topics` handler.
