# PLAN_2026_06_04_069

## Problem Statement

The 6 doc-update sub-skills (`update-architecture-md`, `update-agents-md`, `update-readme-md`, `update-specifications-md`, `update-best-practices-md`, `update-agent-setup-md`) were aligned with `update-docs` dual-mode under PLAN_2026_06_04_068, but their internal organization remains inconsistent:

1. **Missing Outputs & Triggers sections** — unlike `update-docs`, no sub-skill has `Output`, `Exit Declaration`, or `Next Step` sections
2. **Inconsistent phase numbering** — some use `### 1.`, `### 2.` etc., others use `### Phase 1: Plan`
3. **Inconsistent workflow** — `update-best-practices-md` uses a two-phase Plan→Implement structure, `update-agent-setup-md` uses "Scan Global State" instead of "Investigate"
4. **No User Confirmation Gate** — only `update-best-practices-md` has one; the others jump straight from Identify to Assemble
5. **Missing Hand-off sections** — unlike `update-docs`, no sub-skill documents what's completed at each phase

## Goals & Non-Goals

### Goals
- Unify workflow to 5 named phases + User Confirmation Gate across all 6 sub-skills
- Add Outputs & Triggers section (Output, Exit Declaration, Next Step) to all 6
- Add Hand-off section to all 6
- Standard Verifiy checklist across all — keep per-doc specific checks, unify common ones
- All tests pass after changes

### Non-Goals
- No changes to `update-docs` or `review-implementation` orchestrator skills
- No changes to code files — SKILL.md only
- No changes to non-doc-update skills
- Investigation Protocol content stays per-skill (different investigation needs)
- Content Rules (What to Include / What NOT to Include) stay as-is — they're document-specific

### Hand-off (added after Verify)

```
## Hand-off
- Phase 1: Investigation complete
- Phase 2: Current document read and compared
- Phase 3: Gaps identified and documented
- Gate: User confirmed proposed changes
- Phase 4: Document updated
- Phase 5: Verification complete — all checks pass
```

