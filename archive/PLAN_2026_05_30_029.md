# PLAN_2026_05_30_002

## Problem Statement

The current Smart Tool Selection system in AGENTS.md (Phase 0 Hard Gate) classifies tasks by type (Structural → ast-grep, Semantic → cocoindex-code, Architectural → graphify) and selects a single tool. Three problems:

1. **Isolated tools** — no output passes context to the next. Graphify discovers relationships but doesn't feed scoped paths into cocoindex. Cocoindex searches all 126+ files when graphify could narrow scope first.

2. **Token waste** — cocoindex searches the full index for every query instead of only relevant modules.

3. **Missed connections** — structural-only or semantic-only searches miss the other dimension. A graphify→cocoindex→ast-grep pipeline catches all three.

The existing §8.22 "Three-Layer Code Exploration Stack" in PROJECT_BEST_PRACTICES.md describes the concept but lacks I/O contracts, completeness safeguards, fast-path rules, and edge case handling.

## Goals & Non-Goals

### Goals
- Replace Phase 0 Hard Gate with two-tier system: Fast Path (single tool) + 3-Stage Sequential Pipeline
- Define explicit I/O contracts for each stage
- Implement Stage 1 completeness safeguards: 3 query variations × 2 sub-graphs, community expansion
- Evolve §8.22 into §9 "Narrow-Then-Search Pipeline" in PROJECT_BEST_PRACTICES.md
- Update all owning skills, tests, and references in same batch
- Zero app test regressions

- No MCP server or infrastructure changes

## Technical Approach

### Pipeline Design

```
User Query
    │
    ▼
┌──────────────────────────────────────────────────┐
│ Stage 1: Scope (graphify)                        │
│  Input:  User query                              │
│  Action: 3 phrases × 2 sub-graphs (code + doc)   │
│          + community expansion if ≤4 files        │
│  Output: scope: [...], communities: [...],        │
│          confidence: "high"|"medium"|"low"        │
└──────────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────────┐
│ Stage 2: Search (cocoindex-code)                 │
│  Input:  scope from Stage 1 + refined query      │
│  Action: semantic search with paths=scope        │
│  Output: chunks: [(file, line, content, score)], │
│          uncovered_aspects: [...]                │
└──────────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────────┐
│ Stage 3: Verify (ast-grep)                       │
│  Input:  specific pattern from Stage 2 results   │
│  Action: structural match in identified files    │
│  Output: exact_matches: [(file, line, pattern)], │
│          verified_files: [...]                   │
└──────────────────────────────────────────────────┘
    │
    ▼
Read targeted code
```

### Two-Tier Classification

**Fast Path** (single tool):
| Classification | Pipeline | Example |
|---------------|----------|---------|
| Simple | Single tool | "Find console.log" → ast-grep |
| Moderate | 1-2 stages | "How is email validated?" → cocoindex only |

**Pipeline** (sequential):
| Classification | Pipeline | Example |
|---------------|----------|---------|
| Complex | Full 3-stage | "How does matchmaking work?" → graphify→cocoindex→ast-grep |
| Critical | Full pipeline + safety net | Refactoring with blast radius → include unscoped cocoindex check |

### Edge Case Handling

| Condition | Action |
|-----------|--------|
| Graphify returns 0 nodes (all 3+3 phrasings) | Drop to cocoindex unscoped |
| Scoped cocoindex returns 0 chunks | Fall through to ast-grep + grep within scope |
| Scope ≤4 files or low confidence | Community expansion — include all files in returned communities |
| False Complex classification | Agent judgment + cost reminder: "~10k tokens — default to Fast Path" |
