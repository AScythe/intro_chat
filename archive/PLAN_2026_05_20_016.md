# PLAN_2026_05_20_016

## Requirements / Problem Statement

Integrate **Graphify** (knowledge graph generator) into the existing three-layer code exploration stack. Currently, the stack has:
- **Layer 2 (Meso — WHAT):** cocoindex-code — semantic search by natural language intent
- **Layer 3 (Micro — HOW):** ast-grep — structural search/rewrite at AST level

Missing: **Layer 1 (Macro — WHERE):** a macro-level view of the codebase — concepts, communities, connections, and relationships between modules. Without it, agents lack a bird's-eye map of the project before diving into file-level or function-level searches.

Graphify fills this gap: it produces a knowledge graph (via Tree-sitter AST + Leiden community detection) showing god nodes, surprising connections, confidence-tagged relationships, and a report that suggests what to explore next.

## Solution

Add Graphify as **Layer 1 (Macro — WHERE)** atop the existing stack:

| Layer | Tool | Question | Scope |
|-------|------|----------|-------|
| 1 (Macro) | **Graphify** | WHERE are the concepts and how are they connected? | Entire codebase — concepts, communities, relationships |
| 2 (Meso) | cocoindex-code | WHAT does this code do? | Function/block-level semantic search |
| 3 (Micro) | ast-grep | HOW is this code structured? | AST-level pattern search/rewrite |

The integration follows the same proven pattern as the cocoindex-code + ast-grep integration: install via `uv tool install`, add MCP server to `opencode.json`, add Graphify-aware steps to all SDD skills as additive inserts.

### Approach & Design Decisions

- **Install:** `uv tool install "graphifyy[mcp]"` — same pattern as cocoindex-code. MCP extra enables the stdio server.
- **MCP server:** `["python", "-m", "graphify.serve", "graphify-out/graph.json"]` in `opencode.json` — explicit path, same pattern as `ccc mcp`.
- **Git strategy:** Commit `graphify-out/` (per Graphify recommendation for team sharing). Only `manifest.json` and `cost.json` are gitignored.
- **Staleness:** `graphify hook install` for auto-rebuild on every git commit — zero-effort, always fresh.
- **Skill updates:** Additive inserts only — never replace core methodology. Same pattern as cocoindex-code/ast-grep.
- **MCP fallback:** If MCP tools don't surface in OpenCode, skill files reference `GRAPH_REPORT.md` directly instead of `graphify query`.
- **No API key needed:** Code-only indexing uses local Tree-sitter AST parsing. Docs/PDFs/images would need an API key, but this project is primarily code.

### Testing Strategy (TDD)

- **Post-install:** `graphify --version` — confirms CLI is on PATH
- **Post-index:** `graphify query "how does matchmaking work"` — returns relevant results
- **Post-MCP-config:** OpenCode starts without MCP errors (manual smoke test)
- **Post-hook:** `graphify hook status` — confirms hook is active
- **Post-skill-update:** `graphify-out/graph.json` exists, `graphify-out/GRAPH_REPORT.md` exists
- **Regression:** Full test suite passes (25/25 Python, 38/38 JS modules, 81/84 vitest)
