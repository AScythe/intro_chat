# PLAN_2026_05_28_021

## Problem Statement

The Skill Loading Protocol in AGENTS.md is structurally ineffective — buried deep under Process Discipline, worded passively, with no active forcing function. As a result, skills fail to load even when users say explicit trigger phrases. Additionally, 8 skills are invisible to the `skill` tool because they're missing from the system prompt's `available_skills` list.

## Goals & Non-Goals

### Goals
- Promote Skill Loading to its own top-level section in AGENTS.md Cross-Phase Universal Rules
- Rewrite from passive ("when user input matches...") to active ("BEFORE every response, scan...")
- Add explicit priority ordering: Skills > opencode.ai help > Task tool > default
- Add "err on side of loading" rule for ambiguous matches
- Register the 8 missing skills in the system prompt's `available_skills` list

### Non-Goals
- No changes to the SDD phase order or workflow structure
- No new skills
- No changes to skill frontmatter `description` fields (trigger phrases are already correct)
- No changes to `PROJECT_BEST_PRACTICES.md`, `frontend-design`, `shadcn`, or `review-implementation` skills (already done in prior session)

## Success Metrics

- User says "analyze and plan" → `brainstorm-and-plan` skill loads
- User says "implement plan" → `implement-plan` skill loads (after registration fix)
- User says "review implementation" → `review-implementation` skill loads (after registration fix)
- User says "grill the plan" → `grill-and-refine` skill loads (after registration fix)
- All existing tests pass
- Production build succeeds

## Technical Approach

### Phase 1: AGENTS.md Skill Loading Protocol

Restructure the Cross-Phase Universal Rules section:

1. Add a new top-level section **"Skill Loading Priority"** placed BEFORE "Context Window Discipline" and "Process Discipline"
2. Move the existing Skill Loading Protocol bullet from Process Discipline → Execution into this new section
3. Expand it into a full set of active rules:
   - **Scan before every response** — explicitly check all 19 skills against user input
   - **Priority chain** — Skill Loading > opencode.ai help lookup > Task tool delegation > default response
   - **Pre-Task gate** — before using Task/subagent, verify no skill matches the user's intent
   - **Err on side of loading** — when uncertain, load the matching skill
4. Remove the original Skill Loading Protocol bullet from Process Discipline → Execution (it moves, not duplicates)

### Phase 2: Register Missing Skills

Investigate and fix why 8 skills (`implement-plan`, `grill-and-refine`, `check-plan-readiness`, `review-implementation`, `improve-architecture`, `modularize-and-clean`, `frontend-design`, `shadcn`) are missing from the system prompt's `available_skills` list.

Strategy:
- Check if `opencode.json` has a skill registration mechanism
- Check if there's a frontmatter field that controls visibility (e.g., `standalone-entry: true`)
- If no config mechanism exists, add `standalone-entry: true` to all 8 missing SKILL.md frontmatters as a hint
- Verify by restarting session and checking if skills appear
