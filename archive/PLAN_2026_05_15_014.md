# PLAN_2026_05_15_014

## Requirements / Problem

Improve the "waiting for response" UI in RoomPage.tsx after inviting a user to chat. The current view is a bare text-only card. It should visually match the "accepted" state — showing the invited user in a styled person card with status indicators for both parties.

## Solution

Replace the `waitingResponse` view (RoomPage.tsx:223-233) with a layout that mirrors the `accepted` view structure:

1. **PersonCard** — display the invited user (avatar, name, status) in the same `.person-card` box style used in the selection grid
2. **Status indicators** — two `.status-item` rows (like the accepted view): "You: Request sent" (⏳) and "{name}: Waiting for response..." (⏳ with pulse)
3. **Cancel button** — preserved at the bottom

## Implementation Plan

### Files to Create, Modify, or Remove
- `frontend/src/pages/RoomPage.tsx` — [MODIFIED] replace `waitingResponse` JSX body
- `frontend/src/styles/global.css` — [MODIFIED] add `.status-item.pending` pulse rule for the "them" indicator

### Approach & Design Decisions
- Reuse existing `PersonCard` component (already imported at line 10)
- Reuse existing `.ready-status`, `.status-item`, `.status-indicator` CSS classes
- Reuse existing `.pulse-dot` animation by targeting `.status-item.pending .status-indicator`
- No new components needed
- No changes to data flow, state machine, or backend

### Edge Cases
- `requestedPerson` is guaranteed non-null by the `&& requestedPerson` guard on line 223
- PersonCard doesn't use the `available` field in its render — only `.name`, `.status`, `.name.charAt(0)`. Safe.
- Cancel + re-request timing: pre-existing issue (setTimeout can fire after cancel). Not in scope.
