# PLAN_2026_05_12_003

## Requirements / Problem

The Flask->FastAPI migration wiped `# Description:` headers from 5 existing Python files and 3 new files never received them. Multiple docs are now stale: ARCHITECTURE.md still describes Flask/SocketIO architecture, AGENTS.md references non-existent skills and old patterns, SPECIFICATIONS.md tech stack is wrong, and PROJECT_BEST_PRACTICES.md is missing takeaways from the latest session.

## Solution

Batch 1: Add Description headers to all 8 missing Python files.
Batch 2: Rewrite ARCHITECTURE.md sections to reflect FastAPI/WebSocket architecture.
Batch 3: Update AGENTS.md (skills, file ownership, API events, test commands).
Batch 4: Update SPECIFICATIONS.md tech stack + PROJECT_BEST_PRACTICES.md takeaways.

### Approach & Design Decisions

Follow convention established by existing Description headers in the same project: `# Description: <one-line summary of responsibility and wiring>` for Python files. Use present tense, active voice, mention key integration points.

For ARCHITECTURE.md, update in-place section by section — preserve bullet points where accurate, replace where stale. Delete socket_events.py section entirely; add new sections for config.py, schemas.py, connection_manager.py.

### Edge Cases

- If a file already has a Description header despite our scan → verify it's accurate, leave it if correct
- If an ARCHITECTURE.md bullet point is still accurate post-migration → preserve it, don't change for change's sake
- If the app doesn't start after Description header edits → revert that file's header only
- If tests fail from doc updates → impossible (docs are not executed), but re-check content accuracy

### Testing Strategy (TDD)

Non-testable changes (config, renames, typo fixes, infrastructure with no observable behavior) or documentation-only. Verification:
1. Run `python -m pytest tests/ -v` before and after each batch
2. After all batches: verify app starts with `python -m app` (smoke test)
3. After all batches: verify YAML frontmatter of all SKILL.md files still parses

### Success Criteria

1. All 8 Python source files have accurate `# Description:` headers matching their post-migration responsibility
2. ARCHITECTURE.md no longer references Flask, SocketIO, `register_routes()`, `register_handlers()`, or `socket_events.py`
3. ARCHITECTURE.md has sections for `config.py`, `schemas.py`, `connection_manager.py`
4. ARCHITECTURE.md data flow and modifying instructions use FastAPI/WebSocket patterns
5. AGENTS.md references current skill names, includes `.opencode/skills/` in file ownership, has accurate API/WS tables, uses `pytest` for test commands
6. SPECIFICATIONS.md tech stack shows FastAPI + WebSocket
7. PROJECT_BEST_PRACTICES.md has takeaway for mode annotations (Plan/Build)
8. All 21 tests pass
9. App starts successfully with `python -m app`
