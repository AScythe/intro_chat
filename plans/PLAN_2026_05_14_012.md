# PLAN_2026_05_14_012

## Requirements / Problem

Create a Playwright-based E2E test skill that automatically verifies all app pages work in a real browser — Home, Join (with optional name), Room, and Chat pages — including a two-user matchmaking flow.

No E2E test infrastructure exists currently. Only unit tests (vitest) and backend API tests (pytest).

## Solution

Create a standalone skill `.opencode/skills/run-e2e-tests/SKILL.md` that:
1. Installs `@playwright/test` + Chromium if missing
2. Builds the frontend SPA via `npm run build`
3. Runs Playwright tests against the real app with a clean temp database
4. Reports pass/fail per scenario

Playwright manages the server lifecycle via `webServer` config (auto-start `python -m app`, wait for port, kill on exit).

### Design Decisions

1. **Temp database per run** — `DB_PATH` env var set to `os.path.join(os.getcwd(), 'data', 'e2e_test.db')` via Playwright webServer env. Clean slate every run. No pollution of production DB.
2. **Playwright webServer** — Standard pattern: Playwright starts `python -m app`, waits for port 5000, kills on exit. No manual process management.
3. **API polling for match detection** — Chat test polls `GET /api/users/{user_id}/match` instead of relying on WebSocket events. More reliable, avoids async timing issues.
4. **Chromium only** — Single browser for speed. The app is not browser-specific.
5. **Auto-install** — Skill installs `@playwright/test` + Chromium on first run; skips if already present.
6. **Auto-build** — Skill runs `npm run build` before tests. Ensures SPA is fresh.

### E2E Test Scenarios

| # | Scenario | Key steps | Assertions |
|---|----------|-----------|------------|
| 1 | Home page loads | Navigate to `/` | Event code input, Create Event button, Join Event button visible; title contains "IntroChat" |
| 2 | Join page renders — optional name | Create event via API, navigate to `/join/{eventId}` | Name input without `*`, LinkedIn field, Slack field, Save button enabled |
| 3 | Save with auto-generated username | Leave name empty, fill LinkedIn/Slack, click Save | "Profile saved" visible, "Select Room" enabled, POST body has `User_[a-z0-9]{5}` |
| 4 | Save with custom name | Enter "Alice", fill LinkedIn/Slack, click Save | "Profile saved" visible, "Select Room" enabled, POST body has `"username":"Alice"` |
| 5 | Two-user match + chat page | Two contexts: create event → User A joins → User B joins → both select same room → both toggle available → poll for match → navigate to `/chat/{match_id}` | Chat page renders with timer, conversation prompts, connection exchange |

### Edge Cases

| Case | Resolution |
|------|------------|
| Port 5000 in use | Playwright webServer `reject` on port conflict |
| Chromium not installed | Skill runs `npx playwright install chromium` |
| Build fails | Skill reports error, does not run tests |
| Test leaves browser open | Playwright `webServer` kills server on process exit |
| Async timing (match) | Poll API every 500ms, 10s timeout |

### Testing Strategy

The skill *is* the test runner. No separate test for the skill itself. Playwright tests are verified by running them against the real app.

- Framework: `@playwright/test`
- Browser: Chromium (headless)
- Report: Playwright HTML reporter + console summary
- Timeout: 30s per test, 10s per assertion
