# PLAN_2026_05_14_011

## Requirements / Problem

Add a required name input field to the user profile page (`/join/:eventId`) so users can type their own display name instead of getting an auto-generated `User_XXXXX`.

The profile page currently has LinkedIn URL and Slack Handle fields but generates a random username that the user never sees or controls.

## Solution

Add a required "Your Name" text input as the first field on `UserInfoPage.tsx`. Send the user's entered name as the `username` in the API payload. Disable the Save button until a non-whitespace name is entered.

No backend changes needed — `JoinEventRequest.username` is already optional, and the backend uses whatever is provided.

## Implementation Plan

### Approach & Design Decisions

1. **Name is required** — Save button disabled when `name.trim() === ''`. User confirms this choice.
2. **Trim on submit** — `.trim()` before sending to API to prevent whitespace-only names passing validation
3. **maxlength=50** — sensible display name cap
4. **No pre-fill from UserContext** — consistent with existing LinkedIn/Slack fields (all start blank)
5. **Name field first** — most fundamental field on top: Name, then LinkedIn, then Slack
6. **Remove `generateUsername()` import** — no longer needed since name is required; the function stays in `random.ts` for potential future use
7. **No backend changes** — schema, route handler, and database already support custom `username`

### Edge Cases

| Case | Resolution |
|------|------------|
| Whitespace-only name | `.trim()` in handleSave; button disabled when `name.trim() === ''` via `onChange` check |
| Very long name | `maxlength={50}` on the input element |
| Empty name | Save button `disabled` when `!name.trim()` |
| Navigation back to page | No pre-fill (consistent with LinkedIn/Slack) — all fields start blank |
| Re-render after save | Saved card shown, room button enabled — name value persists in `UserContext` |
