# PLAN_2026_05_13_006

## Requirements / Problem

All 44 frontend files (TS/TSX/CSS) lack file-level description comments. Python files have them consistently (`# filename` + `# Description:`). We need to add them everywhere and standardize the convention, then update workflow rules to enforce descriptions on new files.

## Solution

### Single Rule for Description Format

```
[comment-marker] [filename]
[comment-marker] Description: [one-line purpose statement — single responsibility of the module]
```

Applied by language:
- `.py` → `# filename.py` / `# Description: ...`
- `.ts` / `.tsx` → `// filename.ts` / `// Description: ...`
- `.css` → `/* filename.css */` / `/* Description: ... */`

No behavioral changes — only comment additions.

### Workflow Rule Updates

- **`implement-plan.md`** (Section 5 — Surgical Changes): add rule that every new file must have a file-level description matching the convention
- **`modularize-and-clean.md`** (Phase 2 step 1): broaden existing description-preservation rule to cover TS/TSX convention alongside Python

### Approach & Design Decisions

1. **Single rule across all languages** — format matches Python's existing convention, adapted to each comment syntax
2. **Description tone** — present tense, singular responsibility, no trailing period (matching Python convention)
3. **Test file descriptions** — follow `// Description: Tests for [unit under test]` pattern — minimal, clear
4. **Batch by dependency** — source files first (no deps on tests), components next, then pages, then tests, finally config/CSS
5. **No deletion or modification of any existing code** — only insertion of comment blocks at the top of each file

### Edge Cases

| Edge Case | Handling |
|-----------|----------|
| `frontend/tests/setup.ts` — single-line file (`import '@testing-library/jest-dom'`) | Will become 3 lines (description block + blank + import) |
| `frontend/vite.config.ts` — starts with `/// <reference types="vitest/config" />` | Insert description before the triple-slash directive |
| `app/static/css/style.css` — starts with `/* Reset and Base Styles */` section header | Insert description block before the existing comment |
| Files with shebang (`#!/usr/bin/env python3`) | Keep shebang first, description second (already handled in existing Python files) |
