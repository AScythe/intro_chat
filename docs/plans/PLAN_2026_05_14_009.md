### Approach & Design Decisions

1. **No redundant transfers** — content already present in other docs is not duplicated. Only unique/uncaptured content gets a new home.
2. **AGENTS.md retains its core purpose** — behavioral rules, file ownership, failure triage, context window discipline, doc sync triggers, and cross-references all stay. The removed sections were contextual summaries that other docs already own.
3. **DOCUMENT_GUIDELINES.md and update-agents/SKILL.md must be in sync** — both define what AGENTS.md should contain; both must reflect the same boundaries.
4. **README.md is the primary target for commands and setup** — agents can read README.md for exact command syntax. ARCHITECTURE.md also doubles as a technical reference for running instructions.
5. **Non-interactive execution goes to PROJECT_BEST_PRACTICES.md** — it's a universal operational lesson ("always use `-y` flags for non-interactive shells"), not project-specific.

### Edge Cases

| Case | Resolution |
|------|------------|
| Pipeline table still references "Core Commands" after removal | Replace with existing AGENTS.md section names: "File Ownership", "Failure Triage", "Doc Sync Triggers", "Context Window Discipline" |
| update-agents skill says to include "Project overview" etc. | Remove those from "What to Include"; replace with cross-references to SPECIFICATIONS.md, ARCHITECTURE.md, README.md |
| AGENTS.md references itself (lines like "For full architecture → ARCHITECTURE.md") | Keep cross-references — they remain valid and point to documents where the removed content now lives |
| AGENTS.md Scope definition mentions "project context, tech stack, commands, and file boundaries" | Update to remove "project context, tech stack, commands" — file boundaries stays |
