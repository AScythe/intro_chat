# PLAN_2026_05_13_004

## Requirements / Problem

AGENTS.md scope is misaligned. It currently contains:

1. **API Endpoints + WebSocket Events** tables — implementation detail that belongs in ARCHITECTURE.md's Data Flow section
2. **Out of Scope** — product constraint that belongs in SPECIFICATIONS.md
3. **Privacy Requirements** — hard constraints that belong in SPECIFICATIONS.md (merged into existing Privacy section)
4. **No behavioral rules** — missing the core purpose of defining *how* agents should think, plan, implement, and verify across the 7-skill workflow pipeline

The user wants AGENTS.md to primarily define behavioral rules organized by workflow phase (mapping to the skills: analyze-and-plan, grill-and-refine, check-plan-readiness, implement-plan, review-implementation, modularize-and-clean, push-to-git), with only operational constraints (file ownership, commands, environment) remaining.

## Solution

1. **Restructure AGENTS.md**: Keep scope definition, project overview, architecture summary, environment, file ownership, core commands. Remove API endpoints, WebSocket events, Out of Scope, Privacy Requirements. Add "Agent Behavioral Rules" section organized by workflow phase, each mapping to its skill file.

2. **Move API Endpoints + WebSocket Events to ARCHITECTURE.md**: Add reference tables into the existing `## Data Flow (Technical)` section.

3. **Move Out of Scope + Privacy Requirements to SPECIFICATIONS.md**: Add new Out of Scope section. Merge Privacy Requirements into existing `## 🔒 Privacy First` section, restructuring to carry both user-facing framing and hard constraints.

4. **Update DOCUMENT_GUIDELINES.md**: Update Section 8 workflow dependency references and document boundary descriptions to reflect new ownership.

### Approach & Design Decisions

- **Behavioral rules by workflow phase**: Organize into phases matching the 7-skill pipeline. Each phase header names the skill(s) it maps to (e.g., "Phase 1: Thinking & Analysis — analyze-and-plan"). Rules are imperative, concise, and reference the skill for full detail.
- **Privacy merge strategy**: Keep the existing user-facing table in SPECIFICATIONS.md, then add a "Hard Constraints" sub-block with the imperatives from AGENTS.md. This serves both audiences (product evaluators + agents).
- **ARCHITECTURE.md gets reference tables**: The Data Flow narrative already exists (lines 415-424). Add two sub-tables: "REST API Endpoints" and "WebSocket Events" right after the narrative.
- **DOCUMENT_GUIDELINES.md updates**: Only touch Section 3 (SPECIFICATIONS.md scope — add Out of Scope and Privacy to "What to Include"), Section 5 (AGENTS.md scope — add behavioral rules, remove API endpoints), Section 8 (update workflow table refs), and Boundary Tensions table.

### Edge Cases

- **Old references in skill files**: The skills reference AGENTS.md sections by name (e.g., analyze-and-plan reads AGENTS "Out of Scope"). These are in the skill descriptions which are verbal/instructional — they reference the section *name* as a navigation hint. If the content moves to SPECIFICATIONS.md, DOCUMENT_GUIDELINES.md Section 8 must be updated so the workflow table points to SPECIFICATIONS instead of AGENTS. The skill files themselves should NOT be modified (that's a separate task).
- **Content duplication risk**: Privacy requirements exist in both AGENTS.md (hard constraints) and SPECIFICATIONS.md (user-facing table). After the move, there's a single authoritative source in SPECS. AGENTS.md will cross-reference SPECS instead of duplicating.
- **Stale cross-references**: After the move, grep for any remaining references to the removed AGENTS.md sections. Update as needed.
