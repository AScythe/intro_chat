# PLAN_2026_05_13_007

## Requirements / Problem

The project structure has several issues that violate standard software engineering best practices and create friction for maintenance:

1. **CSS misplaced in backend directory** — the only stylesheet lives at `app/static/css/style.css`, served via a FastAPI `/static` mount. This is frontend code stored in the backend package, breaking the separation of concerns between `app/` and `frontend/`.
2. **Path alias configured but unused** — both `tsconfig.json` and `vite.config.ts` define a `@/*` → `./src/*` alias, yet all 57 imports (source + tests) use brittle relative paths (`../../components/Timer`). The config is dead weight; refactoring risk is higher than necessary.
3. **No `pyproject.toml`** — Python tooling (pytest, linter, formatter) has no centralized config. Tests bypass pytest discovery via `if __name__ == '__main__'`.
4. **Timer constants in wrong module** — `CLEANUP_INTERVAL_SECONDS`, `CLEANUP_THRESHOLD_SECONDS`, `MATCH_EXPIRY_MINUTES` live in `state.py` alongside in-memory dicts, instead of in `config.py` where they belong.

## Solution

Apply four structural fixes in independent batches:

| Batch | Change | Type | Files Touched |
|-------|--------|------|---------------|
| 1 | Move CSS `app/static/css/` → `frontend/src/styles/`, import via Vite | Structural | ~5 |
| 2 | Add root `pyproject.toml` with pytest + basic tool config | Config | 1 (new) |
| 3 | Move timer constants `state.py` → `config.py`, update imports | Code org | 3 |
| 4 | Convert all relative imports to `@/` alias in source + tests | Code quality | ~21 |

| Before | After |

### Approach & Design Decisions

- **Independent batches, sequential application**: Each batch is independent and can be tested before proceeding to the next.
- **CSS via Vite import (not link tag)**: Importing CSS in `main.tsx` gives us Vite HMR in dev and content-hashed bundles in production. No more manual `<link>` tag.
- **Remove `/static` mount entirely**: The `app/static/` directory only contained the CSS. No reason to keep a dead mount.
- **`@/` alias for both source and tests**: Vitest inherits Vite's resolve config, so `@/` works in test imports too. No separate tsconfig-paths registration needed.
- **No tsconfig changes**: The `paths` entry already exists. We're simply using it.

### Edge Cases

1. **CSS import order in production build**: Vite inlines CSS in the JS bundle by default (or emits to `dist/assets/` with a hash). The production `index.html` in `frontend/dist/` gets `<link>` tags auto-generated by Vite. No manual syncing needed.
2. **Styling flash (FOUC)**: If Vite extracts CSS to a separate file, the auto-inserted `<link>` comes from `index.html` — same as before. No regression.
3. **`../src/` in tests**: Test files use `../../src/` or `../src/` to reach source. After conversion, `@/` resolves to `frontend/src/` across all files, including tests. Only works because Vite's `resolve.alias` is active for all files in the Vite/Vitest pipeline.
4. **No `pyproject.toml` breaks nothing**: The config is entirely additive. Existing `python tests/test_*.py` direct execution continues to work. `python -m pytest` becomes a new option.
5. **Constants move — stale gitignore**: `data/introchat.db` is tracked by `.gitignore`. No change needed.
6. **CSS removal from `state.py`**: The timer constants are only used in `tasks.py`. `state.py` does not reference them in any function — only as module-level definitions. Safe to remove without breaking imports in state.py.
